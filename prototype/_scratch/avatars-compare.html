AVATAR ART DIRECTION

Design exploration only — scratch file, does not touch the live game. Comparing two avatar art approaches for player/cricketer cards. Fictional archetypes only, no real player likenesses.

Trade-off in one line — Option A ships now, is free, scales to infinite generated players, and stays lean. Option B looks the best but costs real file-size, is a finite hand/AI-illustrated archetype library (not generated per player), and needs an image-generation or illustration pipeline.

Today's shipped baseline — what we're replacing

Being replaced

Current in-game art: generatePlayerSilhouette() (bat + head-dot + limb lines) and generateCrest() (initial letter in a shield) — prototype/index.html ~L4508 / ~L4447. Crude line-art, same 4-6 lines regardless of player. Both options below are upgrades on this.

OPTION A

Shippable · ₹0 · Tiny

Upgraded procedural SVG avatar — layered face/skin tone, helmet or cap, team-color jersey, pose hint, rarity frame. Still pure inline SVG generated in code. 4 variants shown to prove it scales to any generated player (any role × any rarity × any team color).

Generated on the fly, works for infinite players — no art budget, no asset pipeline. Average weight across the 4 variants above: — per avatar as a raw SVG string (baseline stick-figure for reference: —).

OPTION B

Richest · Heaviest · Finite

Baked "painted portrait" asset — one hand-crafted, high-fidelity illustrative SVG standing in for what a baked AI-generated or hand-illustrated image asset would look like. This is the ceiling: dramatic single-key lighting, shaded skin/cloth, grain texture, named archetype plaque.

Represents a baked image asset — a real production version of this would be a raster/WebP portrait weighing ~30–150KB each, drawn from a FIXED library of archetypes (not generated per player), and it adds directly to the 500KB page budget (§7.3). This demo SVG itself measures — as vector code — that number is not the honest cost; the KB range above is.

Recommendation

Ship Option A. It is a genuine, visible upgrade over today's stick-figure baseline, costs nothing, has zero asset pipeline, and — critically — generates correctly for every procedurally-created player the auction system produces. Option B is the honest "if we ever had an art budget" ceiling: keep it as a reference/aspiration, not a near-term commitment, because it requires a finite illustrated library and a real production pipeline (AI image gen or a hired illustrator) that Option A does not need.
